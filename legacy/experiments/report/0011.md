# 0011 — Bounded cache: SSC's win is NOT constant-memory (2026-06-18)

Practicality question: SSC routes over the per-segment state cache, which grows O(N) with length
(N = #segments) and costs O(N²) to read-recompute. Can we cap the cache at a constant `B` snapshots
(evicting the rest) and keep the win — making the retrofit constant-memory / linear-cost?

## Setup
SSC k=4 (low-rank 64, passkey-trained) on natural-language passkey **@8192 (32 segments, chunk 256)**.
Eval-time cache cap `B ∈ {4,8,16,32=full}` × evict `∈ {uniform (even-spaced), recent (last B)}`. n=16.

| cap B | uniform | recent |
|-------|---------|--------|
| 4  | 0.053 | 0.105 |
| 8  | 0.237 | 0.211 |
| 16 | 0.500 | 0.605 |
| 32 (full) | **1.000** | **1.000** |

(vanilla @8192 = 0.789.)

## Finding
- **The win requires (near-)all snapshots.** Full cache → 1.000 (+0.21 over vanilla); **cap=16 already
  drops to 0.50–0.61 — below vanilla**; cap=8 → ~0.22; cap=4 → ~0.08. Degradation is ~proportional to
  B/N.
- **Why:** a single needle lives in *one* segment; uniform/recent eviction drops it with prob
  ~(N−B)/N, and once that frozen snapshot is gone the routing has nothing to recall. Recency beats
  uniform slightly (the query is near the end), but neither rescues a small B.
- So **SSC is not constant-memory.** The top-k *read* router cuts read cost (O(N²)→O(N·k)), but the
  **cache itself must stay ~O(N)** — SSC sits on the RNN(O(1)-mem)↔attention(O(L)-cache) spectrum,
  exactly the MC-paper trade-off. This is the honest answer to "why not just use attention?": SSC's
  cache is L/C compressed states (256× fewer than per-token KV) and reads are top-k sparse, but it is
  *not* the constant-memory advantage a vanilla linear model has.

## Implication
- **Eval-time bounding can't be rescued by training**: eviction discards the needle's frozen snapshot
  irreversibly, and our segments don't *consolidate* (no write-back into kept slots). True bounded
  memory would need a **consolidating/landmark mechanism** that merges or rewrites evicted state into
  retained slots without losing the needle — a different mechanism (cf. the MoCM future-work design;
  and note hierarchical *merge* already failed, 0008, because merging dilutes the needle).
- For the paper: state the cost honestly — SSC is an effective long-context recall *retrofit* whose
  memory scales with length (compressed, sparse-read), not a constant-memory method.
