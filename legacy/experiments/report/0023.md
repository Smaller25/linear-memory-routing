# 0023 — Decorrelated-write (idea A / C4) does NOT transfer to a real GDN-2 with decay (2026-07-15)

Follow-up to 0022. There, on a **decay-free** from-scratch delta-net, the decorrelation regularizer
**C4** (the winning candidate of idea A) *helped* multi-key recall **under overload**. But 0022's stated
limit was: the testbed had **no decay**, and F7 found decay is the **dominant** reason for low state
eRank in the real model (+7.8 vs anisotropy +1.5). This report ports C4 to a **real GDN-2** (FLA
`GatedDeltaNet2`, which has the real decay/erase gating) trained from scratch on MQAR, to test whether
the 0022 benefit survives when the dominant lever (decay) is present.

## Purpose
- **Question.** Does C4 (decorrelation regularizer on keys) improve multi-key recall on a **real GDN-2
  with decay**, i.e. does the 0022 positive transfer out of the decay-free toy?
- **Why C4 only.** C4 was the 0022 winner and is loss-only, so it ports to the real FLA layer with **no
  kernel surgery** (a forward hook on `k_proj` + a Gram penalty). C1/C2 need in-kernel changes; C4 is the
  cleanest, strongest test of idea A on the real architecture.
- **Decision rule for this session.** If C4 helps here → idea A conditionally validated on real GDN →
  proceed to (b) finetuning a pretrained GDN. If it does not → (a) fails; do **not** spend (b).

## Setup
- **Backbone (the change from 0022).** Real **FLA `GatedDeltaNet2`** (repo's vendored **fla 0.5.2**,
  used on VESSL via `PYTHONPATH` to avoid the installed 0.5.1 chunk-kernel `use_exp2` bug). 2 layers,
  RMSNorm, `expand_v=1.0`, chunk kernel for training. **Has real decay + erase gate** — the mechanism the
  0022 delta-net lacked.
- **Task / training.** Same MQAR as 0022 (vocab 512, seq 256), curriculum kv {16,32,48}, batch 32,
  AdamW lr 1e-3 wd 0.1, grad-clip 1.0, **5000 steps** (GDN has a delayed phase transition ~2000 steps;
  5000 to clear it and give C4 room), bf16, single A100 (VESSL).
- **C4 implementation.** Forward hook captures each layer's `k_proj` output; per head L2-norm, mean
  key-Gram `Ĝ`, penalty `λ·‖Ĝ − I‖²` added to the CE loss. Retrieval-preserving (keys only re-shaped
  for the penalty; the kernel is untouched).
- **Metric.** recall = exact-match at query positions, eval kv {32,48,64}, 192 seqs. **erank** = entropy
  eRank of the final last-layer recurrent state (mean over heads), monitor only.
- **Regimes / sweep (to be fair to A).**
  - **hd=32, num_heads=1, λ=0.5** — baseline learns well (moderate load).
  - **hd=32, λ=0.1** — weaker regularizer (checks whether λ=0.5 was just over-regularizing).
  - **hd=16, λ=0.5** — extreme overload (the 0022-R3 analog, where C4 *helped* in the toy).
- **Baseline.** identical model, no hook, no penalty.

## Result
| regime | variant | recall kv32/48/64 | erank | verdict |
|---|---|---|---|---|
| hd=32, λ=0.5 | baseline | 0.892 / 0.700 / 0.497 | 16.21 | — |
| | C4 | 0.809 / 0.600 / 0.430 | **6.24** | **hurts** |
| hd=32, λ=0.1 | baseline | 0.892 / 0.700 / 0.497 | 16.21 | — |
| | C4 | 0.849 / 0.650 / 0.480 | **2.81** | **hurts** |
| hd=16, λ=0.5 (extreme) | baseline | 0.110 / 0.068 / 0.044 | 6.88 | — (barely transitions) |
| | C4 | 0.045 / 0.030 / 0.018 | 6.45 | **hurts (blocks learning)** |

## Findings
1. **C4 fails on real GDN-2 — consistently, in every regime.** recall drops at every kv and every λ
   (hd=32 λ=0.5: 0.497→0.430; λ=0.1: 0.497→0.480; hd=16: 0.110→0.045). The 0022 overload benefit does
   **not** transfer.
2. **Weaker λ does not rescue it.** λ=0.1 still hurts recall and, strikingly, crashes erank *further*
   (16.2→2.81). So this is not mere over-regularization at λ=0.5 — the *direction* is harmful.
3. **C4 collapses state eRank on GDN-2 (opposite of the delta-net).** On the decay-free 0022 delta-net,
   C4 *raised* erank (32→36); here it *crashes* it (16→3–6). Forcing isotropic keys on a decay-bearing
   model does not spread the state — it makes the trained model pack into fewer directions and optimize
   worse (higher final loss).
4. **In extreme overload the real GDN-2 barely learns MQAR at all** (hd=16 baseline loss stuck ~4.85 vs
   random ~5.5, recall 0.11), and C4 makes the phase transition *later* still (loss 5.24). So real
   GDN-2's failure at high load is not a spare-rank-we-can-fill problem — it is a decay/gating-bound
   learning problem, which C4 cannot touch and actively worsens.

## Interpretation
The 0022 delta-net had **no decay**, so key anisotropy was the *only* rank-limiter and decorrelating
keys (C4) helped under overload. A real GDN-2's rank is **decay-bound** (F7: decay +7.8 ≫ anisotropy
+1.5). C4 (i) does not touch decay and (ii) fights the model's learned key↔gate coupling, so it collapses
both state rank and recall. This **confirms and strengthens** 0022's stated limit: idea A targets the
*secondary* lever; on the real architecture it is not merely ceiling-bounded but **actively harmful**.
General lesson: on a decay-bearing linear-recurrent model, **eRank is not a knob you can raise via write
geometry** (consistent with `SSM_Rank_Analysis/REPORT`: eRank ≠ capacity). The design lever must be
**decay/retention**, not write-orthogonalization.

## Decision
**(a) fails → (b) not run.** Per the session's decision rule, finetuning a pretrained GDN with C4 (b)
would only re-confirm this negative at higher cost and higher risk (fighting an already-learned key
geometry even harder). Deferred.

## Caveats (honest)
- Only **C4** was tested on real GDN-2 (C1 whitening / C2 learned-map need in-kernel changes). C4 is the
  0022 winner and fails hardest, and C1/C2 would fight the same learned geometry — but idea A as a
  *family* is not 100% excluded, only its cheapest/strongest member is clearly refuted here.
- Toy scale (2-layer, vocab 512, single seed, 5000 steps). C4's higher loss could be partly slower
  convergence, but the effect (recall ↓ + erank collapse) is consistent across 3 configs.

## Next (pivot to the decay lever)
- **Selective retention.** Make decay input-dependent so important directions/tokens keep `aₜ→1`
  (retain longer) while filler decays — spend *retention time* on the idle rank rather than trying to
  fill it by write geometry. Works *with* GDN-2's gating, not against it.
- **Idea C (erank as saturation signal → dynamic chunking):** fire a new chunk/state when erank
  plateaus; complementary and touches the retention axis.
