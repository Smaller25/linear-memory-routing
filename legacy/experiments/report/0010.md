# 0010 — Multi-key recall: SSC's win does NOT extend beyond single-needle (2026-06-17)

0009 left open: niah_multikey collapsed because SSC was trained only on the *single* passkey. So we
trained SSC directly on a multi-key distribution (`make_text_multikey`: N named facts "The <word>
code is <number>." scattered in real filler, query one) and re-checked RULER `niah_multikey_2`.

## Training multi-key SSC did not converge (two aux settings)
SSC k=4, low-rank 64, train_len 2048, on `make_text_multikey` (8 keys). Train-acc never stabilised
(bounced 0.0–0.75); tried the Switch load-balance `aux_scale` at **1e-2** and **1e-4** (aux fell
10.4→0.11, CE then dominated) — same non-convergence either way.

## Results
**Our `make_text_multikey` (held-out), in-script eval:**
| length | vanilla | +RM | +SSC (multikey-trained, aux 1e-4) |
|--------|--------|-----|------------------------------------|
| 2048 | 0.945 | 0.874 | 0.425 |
| 4096 | 0.929 | 0.276 | 0.307 |

**RULER `niah_multikey_2` (standard), multikey-trained SSC:**
| length | vanilla | +RM | +SSC |
|--------|--------|-----|------|
| 4096 | 0.115 | 0.000 | 0.000 |
| 8192 | 0.019 | 0.000 | 0.006 |

## Why multi-key breaks SSC (honest analysis)
1. **Vanilla is already competent on our multikey at 2048 (0.945)** — its single continuous state
   holds all 8 facts within mamba2's competent range. **Segmenting throws that away**: SSC resets
   state per segment and must *reconstruct* multi-fact access by routing — and ends up *below*
   vanilla (0.42). MC only helps where the fixed state has actually saturated (long single-needle),
   not where it's still doing fine.
2. **Segment granularity can't disambiguate keys that share a segment.** MC caches one state per
   *segment*, not per *fact*; several keys land in the same 256-token segment, so routing to it
   brings all of them — no per-key separation.
3. **Routing here is key-matching, not needle-finding** (query "thistle" → the segment stating the
   thistle fact) — harder than single-needle, and the non-convergent train-acc reflects it.
4. On **RULER niah_multikey_2** the base model is near-floor anyway (vanilla 0.115/0.019), so there
   is no headroom; SSC stays ~0.

## Verdict (scope of the contribution)
**SSC's net win is specific to single-needle long-context recall where the fixed state saturates**
(passkey 8k: +0.25 @1.3b, +0.50 @2.7b; RULER niah_single_1: +0.06–0.18 zero-shot). It does **not**
extend to multi-key recall: where vanilla is competent, segmenting hurts; where the task is hard,
neither works. A per-*fact* (not per-segment) memory, or finer chunking that isolates each key, would
be needed for multi-key — a different mechanism than segment-level SSC.
