# 0022 — Decorrelated-write (idea A): does writing into idle state directions help multi-key recall? (2026-07-15)

Design-part experiment (explicitly separate from the erank *analysis* part, 0021/F6–F10). The analysis
concluded: a fixed recurrent state keeps **low effective rank** for two reasons — ① **decay** (dominant,
F7 +7.8) and ② **key/value anisotropy** (secondary, F7 +1.5) — so a large fraction of the state's rank
sits idle (F6–F10: ~83% idle on the real GDN2-370m). Idea **(A)**: *write new information into the
idle/orthogonal directions* (decorrelate the write) to use that spare rank and reduce interference. This
report tests whether (A) actually buys **recall** (the real target; erank is only a monitor, since
`SSM_Rank_Analysis/REPORT`: eRank ≠ capacity).

## Purpose
- **Question.** Does actively decorrelating the write (spreading keys off already-occupied directions)
  improve **multi-key associative recall** over a plain delta-rule baseline?
- **Not** "raise erank" — erank is a monitor only. The pass/fail metric is **recall**.
- **Scope of the claim under test.** (A) is a *write-geometry* intervention: it targets cause ②
  (anisotropy), **not** cause ① (decay). So this bounds (A)'s ceiling by design — see Limits.
- **Sub-question.** Among candidate mathematical implementations of (A), which one (if any) works, and
  how cheap is it?

## Setup
- **Testbed (deliberately minimal, full write-rule control).** Pure-PyTorch **delta-net** implemented
  from scratch (no FLA kernels), so the write rule is fully controllable and the decorrelation
  interventions can be inserted exactly. 2 layers, short depthwise conv (kernel 4) on q/k/v, L2-normed
  keys/queries, per-head sigmoid write-gate β. **No decay** (`aₜ≡1`) — this isolates cause ② (anisotropy)
  and removes cause ① by construction (see Limits).
- **Task.** MQAR (multi-query associative recall), Zoology-style: `kv` key–value pairs planted in the
  context, then each key re-queried at a later position; loss = next-token CE at query positions only.
  vocab 512, sequence length 256 (R2/R3) / 192-train.
- **Training.** AdamW lr 3e-3, wd 0.1, grad-clip 1.0, batch 64, **2000 steps**, curriculum over `kv`
  (cycling). Single A100 (VESSL), bf16.
- **Eval.** held-out `kv` sizes, recall = exact-match accuracy at query positions (192 seqs). **erank** =
  `exp(entropy(normalized singular values))` of the final per-head state, mean over heads/layers.
- **Capacity regimes (the key manipulation).** Same everything, only per-head **state size** and load
  varied, to move the baseline across the capacity wall:
  - **R1 — slack:** 2 heads × dim 64, eval kv 8/16/32. (baseline saturates.)
  - **R2 — near-saturation:** 1 head × dim 32, eval kv 32/48/64. (baseline ~0.96.)
  - **R3 — overload:** 1 head × dim 16, eval kv 32/48/64. (baseline collapses — the real test.)
- **Candidates (top-3 of six enumerated; each retrieval-preserving: same transform on write-key AND
  read-query).**
  - **C4 — decorrelation regularizer** (cheapest; no arch/inference change). Add loss term
    `λ·‖Ĝ − I‖²`, Ĝ = normalized mean key-Gram per head, λ=0.5. Encourages isotropic (spread) keys.
  - **C1 — key whitening** (arch change). ZCA whiten keys from the batch key-covariance,
    `k̃=W k, q̃=W q`, `W=(C+εI)^{-1/2}`. Makes keys isotropic; applied to k and q so retrieval is
    basis-invariant.
  - **C2 — learned decorrelating map** (arch change). Per-head learned linear `U` (init identity),
    `k̃=U k, q̃=U q`, trained end-to-end. No explicit decorrelation pressure — tests whether CE alone
    induces spreading.
- **Baseline.** identical model, no transform, no regularizer.

## Findings
1. **(A) is conditionally valid — it helps only under genuine capacity pressure.** In the overload
   regime R3 (baseline collapses to 0.081 @kv64) decorrelated writes **recover recall**: C4 kv64
   0.081→0.181 (2.2×), C1 →0.153 (1.9×); C1 also best at kv48 (0.306 vs 0.277). Where the state has
   slack (R1) the effect is neutral, and near-saturation (R2) it **hurts** (whitening kv64 0.961→0.765):
   forcing decorrelation is a needless constraint that fights the learned key geometry until the model
   is actually against the wall. (A) is a *capacity-pressure* intervention — the regime long-context hits.
2. **Winner = C4 (decorrelation regularizer).** Best overload recall, moves erank in the intended
   direction, and costs **nothing** at inference (one loss term, no arch change). Cheapest of the three
   and the most effective.
3. **C2 (free learned map) is null.** With no explicit decorrelation pressure the map drifts to ≈identity
   (CE does not reward spreading). So the effect requires an **explicit** pressure (C4's penalty / C1's
   whitening) — a free parameterization will not discover it.
4. **erank ↔ recall is regime-dependent, not a universal meter.** They co-move (both up) **only in
   overload (R3)**; in slack (R1) raising erank (C4 35.9) leaves recall flat. Consistent with the
   analysis-part conclusion **eRank ≠ capacity** — erank is a spare-capacity *indicator only when the
   state is loaded*.

## Limits (must state)
- **No decay in this testbed.** By construction (`aₜ≡1`) this isolates cause ② (anisotropy) and removes
  cause ① (decay). But F7 found **decay is the dominant** reason for low erank in the real model
  (+7.8 vs anisotropy +1.5). So (A) targets the *secondary* lever; its ceiling on a real
  decay-bearing GDN2 is bounded accordingly. The **primary** design lever remains **decay/retention**.
- **Toy scale.** 2-layer from-scratch delta-net, synthetic MQAR, vocab 512, single seed, 2000 steps.
  Directional evidence, not a headline number. Real-model transfer untested.
- **Not a claim about GDN2's actual state.** These regimes are engineered overload; whether the real
  frozen/ from-scratch GDN2 sits in the R3-like regime at long context is a separate measurement.

## Next
- **Move the winner (C4) to a decay-bearing testbed** (add per-channel gating `aₜ`, or the real GDN2-370m
  from-scratch trainer) and check the overload gain survives — and whether **combining C4 with a
  decay/retention intervention** (the dominant lever) gives synergy.
- **Find the real operating regime.** Measure where a trained GDN2 lands on the R1→R3 axis at long
  context (is it overloaded, i.e. where C4 pays off?).
- **Idea C (deferred):** erank as a saturation signal → dynamic chunking (fire a new chunk when erank
  plateaus). Complementary to (A) and touches the decay lever.
