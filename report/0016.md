# 0016 — Unsupervised boundary learning fails three ways; the signal needs supervision (2026-06-28)

0015 showed the boundary head recovers per-fact, content-adaptive boundaries on irregular MQAR **when
distilled from oracle positions**. The question this report answers: **can those boundaries be learned
WITHOUT the oracle?** Three formulations, all from-scratch GDN-2 (d256/4L), irregular MQAR
(`--ctx-filler 128`), train-kv 4–64, eval 64–256. Answer: **no — none is self-sustaining.**

## Three unsupervised formulations, three failure modes
| method | recall (kv64/128/256) | hard boundaries @0.5 | what happened |
|--------|----------------------|----------------------|---------------|
| **soft** (landmark-biased attention + L1) | 0.99 / 0.99 / 0.93 | 0 (p<0.5) | recall is real but via **full attention** over all tokens — boundaries never form; the read bypasses the cache. Not a caching result. (jobs 1269/1270) |
| **STE hard-cache + L1 budget** | 0.00 / 0.00 / 0.00 | ~0 | **collapses**: L1 has no floor → p→0 → empty cache → no recall gradient to push p back up (weak discrete STE signal can't bootstrap). loss stays random. (1274–1276) |
| **warm-start** (distill phase-1, oracle off phase-2) | 0.98 / 0.63 / 0.20 | 0 | warmup learns (loss→0); after the oracle is removed the head **fully drifts** (below). (1278/1280) |

## The decisive measurement — threshold-free top-k(p) overlap
A boundary at threshold 0.5 firing 0 could mean "decalibrated but still ranks facts highest" or "fully
drifted". So we measure, calibration-free, the overlap of the **k highest-p positions** (k = #facts)
with the true facts:

| | top-k(p) ∩ facts, kv 64/128/256 |
|---|---|
| **supervised learned** (reference, 1281) | **1.00 / 1.00 / 1.00** |
| **warm-start, oracle removed** (1280)    | **0.00 / 0.00 / 0.01** |

The metric is validated by the supervised reference (1.00 — it ranks facts highest). Warm-start scores
**0.00**: the head's high-p positions have *no* overlap with facts — it **fully drifted**, not merely
decalibrated. The warm-start model's non-trivial recall (0.98 @kv64, decaying to 0.20 @kv256, ~2×
vanilla but far below the supervised ~1.0) comes from the **co-trained backbone**, not the cache —
which is effectively unused once the oracle is gone.

## Verdict
The "where to cut" boundary signal is **learnable only with continuous oracle supervision** (0015).
Without it, every formulation fails: soft sidesteps boundaries via attention, STE+budget collapses,
and a supervised warm-start does not survive oracle removal (boundaries drift to 0.00 overlap). This is
the known difficulty of unsupervised discrete-latent-structure learning. **Honest implication:** the
Dynamic-MoSC adaptivity result (0015) holds *with oracle-boundary supervision*; the unsupervised
version is an open problem.

Also reaffirmed (the soft result): these synthetic recall tasks are only discriminative **under a
sparse-cache budget** — given full attention they are trivially solved, proving nothing about caching.
All caching claims must hold the cache/read budget fixed.

## Not yet tried (if revisiting unsupervised)
- **Target-rate budget** (anchor `mean(p)` to a target firing rate, not L1→0) to prevent the collapse.
- **Surprisal / state-change trigger** (backbone NLL or ‖Δstate‖) with a learned threshold.
- **Reconstruction auxiliary** (a segment is "good" if its summary reconstructs its tokens).
Otherwise: accept the supervised method and validate it on standard benchmarks (Selective Copying,
MAD noisy/fuzzy recall) + the true per-row recurrent-state cache.
