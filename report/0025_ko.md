## 한 줄 결론

**상위 주장 (M) "router는 needle 검출기이지 key 판별기가 아니다"는 기각된다.** key를 판별할
필요가 전혀 없는 과제(multivalue: 컨텍스트에 key 1개, 값만 여럿)에서조차 router의 hit@2는
0.435/0.442로, "needle 검출은 완벽하고 key 판별은 0"을 가정한 needle-null 기대치 0.723보다
**약 4 SE 아래**다. 즉 문제는 "여러 key 중 어느 것인가"의 판별 단계가 아니라 그 **이전 단계인
descriptor 전반**에 있다. 무료 개입 후보였던 `u_t := q_t`(X1b)와 값싼 기하 교정(X1c: centering은
대수적 no-op, top-1 PC 제거는 null-to-negative)은 **둘 다 실패**했고, layer 9–13은
descriptor-only 특징(사실상 위치)으로 routing 점수가 R² ≈ 0.99까지 설명되는 **국소적으로 query를
쓰지 않는 구간**임이 확인됐다. 남은 처방은 contrastive router supervision과 WY/UT 읽기 기하
기준의 descriptor 재구성 두 가지뿐이며, 둘 다 재학습을 요구한다.

## 셋업

- **모델**: `mc-gdn2-370m-fineweb-edu-30b-v2-meanpool`의 **5B / 30B** ckpt.
  16 layers, topk=2, chunk 256, descriptor = L2-정규화 key mean-pool.
- **코드 고정**: long-gdn worktree `e71713e`, fla `4b02d15d` pin (이후 fla는 GLA API 비호환).
  0024와 동일 pin — 비교 가능성 유지.
- **실행 환경**: **VESSL A100** 단일 GPU 컨테이너. 학습 job 없음 — X1–X4 전부 추론/후처리다
  (스펙 §8). 코드는 컨테이너 로컬(`/root/work`), geesefs에는 bundle/tar/ckpt/결과만 둔다
  (geesefs에 git clone 시 소파일 대량 쓰기로 실패하는 문제 때문).
- **X1 덤프**: answer position에서 16 layer의 `c_i`(정규화 전 `csub_raw` / 후 `c_full`),
  router query `u_t`, retrieval query `q_t`, canonical `stock_scores`, top-2 인덱스를 저장.
  추가 forward pass 0회. 총 **264 npz** (모델당 132 = single_1 50 + multikey_1 50 +
  paired_S 16 + paired_D 16), VESSL 상 ~3.98 GB.
  - 초기 덤프는 vendored RULER `niah.py`의 변수 섀도잉 때문에 `index` 필드가 유니크하지 않아
    파일명 충돌로 일부 샘플이 덮어써졌다(47/49 unique). enumeration index `ri`로 키를 바꿔
    **전량 재생성**했고, 재생성본은 E1 best-layer와 8/8 일치한다.
- **`u`/`q` head 축 처리**: `u`,`q`는 `[L,H,K]`로 저장되며 점수 계산 시 `H,K`를 flatten해
  `c_full`과 단순 내적한다. 이는 serving 경로의 `einsum('bthk,bnhk->btn', ...)`(head+K 합산)과
  **동일**하다. head별 max/mean 같은 별도 reduction은 쓰지 않았다.
- **데이터**:
  - Dataset A = RULER 표준 `niah_single_1` / `niah_multikey_1` 각 50개 @2048.
  - Dataset B = 쌍맞춤 paired 데이터, 조건당 **16쌍** — **S**(distractor를 gold와 같은
    segment에) / **D**(전부 다른 segment). gold/distractor는 segment 1–5에만 배치(0024 규약 유지).
  - X2 추가분 = `niah_multiquery`, `niah_multivalue`, `niah_multikey_1` @ {2048, 4096, 8192}
    각 50개 + `niah_multiquery_q2`(q=2 스윕) + **`niah_single_2`**(essay-haystack 단일 needle).
- **`niah_single_1` vs `niah_single_2` 주의**: `single_1`은 **noise-haystack**(반복 잡음 문자열),
  `single_2`는 **essay-haystack**이다. multiquery/multivalue/multikey는 전부 essay-haystack이므로
  **직접 비교 가능한 통제군은 `single_2`뿐**이다. `single_1`은 0024/E1과의 연속성 참조로만 싣는다.
- **노이즈 규약**: bf16 재실행 노이즈 ~2.3pp. n≤16 셀은 pp 대신 **"≤1 sample flip"**
  (n=16에서 6.25pp) 기준으로 판정한다. n이 작으므로(16–50) 절대값 주장 금지, 방향성으로 서술.

## X1 — descriptor-only 예측 + `u_t := q_t` 재계산

원본: `results/x1_router_probe.json`, 그림 `results/x1_router_probe.png`.

### X1a. descriptor-only 예측 (국소 H_blind 검정)

query를 전혀 쓰지 않는 세 특징 `pos_i`(정규화 위치), `norm_i`(정규화 전 descriptor norm),
`outlier_i`(descriptor 평균 방향에서의 코사인 거리)로 실제 routing 점수를 회귀했다.
아래는 8개 셀(2 모델 × 4 데이터셋) 전체에 대한 layer별 R² 범위다.

| layer | R² min | R² max | R²≥0.9인 셀 수 |
|---|---:|---:|---:|
| 0 | 0.317 | 0.720 | 0/8 |
| 1 | 0.290 | 0.861 | 0/8 |
| 2 | 0.917 | 0.985 | **8/8** |
| 3 | 0.988 | 0.998 | **8/8** |
| 4 | 0.790 | 0.979 | 6/8 |
| 5 | 0.996 | 0.999 | **8/8** |
| 6 | 0.517 | 0.978 | 4/8 |
| 7 | 0.996 | 1.000 | **8/8** |
| 8 | 0.491 | 0.954 | 2/8 |
| 9 | 0.991 | 0.999 | **8/8** |
| 10 | 0.997 | 1.000 | **8/8** |
| 11 | 0.260 | 0.998 | 5/8 |
| 12 | 0.990 | 0.999 | **8/8** |
| 13 | 0.974 | 0.997 | **8/8** |
| 14 | 0.123 | 0.909 | 1/8 |
| 15 | 0.095 | 0.916 | 1/8 |

- **국소 H_blind는 확정된다.** layer 2·3·5·7·9·10·12·13은 8개 셀 **전부**에서 R² ≥ 0.9이고,
  대부분 0.99 이상이다. 이 layer들의 routing 점수는 query를 보지 않는 세 숫자로 재구성된다.
  layer 4·6·8·11은 셀에 따라 갈리고(최저 0.260), layer 0·1·14·15는 일관되게 낮다.
- **설명력의 정체는 사실상 `pos_i` 하나다.** layer 2–13 구간에서 `pos` 단독 R²의 중앙값은
  **0.985**(min 0.067, max 0.998)인 반면 `norm` 중앙값 0.369, **`outlier` 중앙값 0.097**
  (max 0.571)이다. 즉 이 구간의 router는 "위치 함수"에 가깝고, H_outlier가 상정하는
  중심-거리 신호는 여기서 거의 잡히지 않는다.
- **top-2 집합 예측도 같은 그림이다.** 세 특징 결합 argmax-2의 Jaccard는 layer 2–13의 96개
  (셀 × layer) 중 **62개에서 정확히 1.000**(중앙값 1.000, 최저 0.333)이다. 점수 회귀만이 아니라
  실제 선택 집합까지 query 없이 복원된다.
- **결정적 대비**: stock hit@2가 최대가 되는 layer는 8개 셀 중 6개에서 **layer 14–15**
  (mc-5B single L14 / paired-S L14 / paired-D L14, mc-30B single L15 / multikey L14 /
  paired-S L14; 예외는 mc-5B multikey L2와 mc-30B paired-D L0). 그런데 layer 14–15는 R²가
  0.095–0.916으로 descriptor-only 설명이 **가장 안 되는** 구간이다.
  → **전역 H_blind는 기각**(routing 신호는 실재하고 query에 의존한다), **국소 H_blind는 확정**
  (layer 9–13은 그 신호에 기여하지 않는 위치 함수 구간이다). 0024가 관측한
  "layer 9–13 평탄 구간"의 정체가 이것이다.

### X1b. `u_t := q_t` 재계산 — 처방 ① 기각

같은 덤프에서 descriptor는 그대로 두고 router query만 retrieval query로 바꿔 점수를 다시 매겼다
(추가 forward 0회). best-layer hit@2:

| model | dataset | chance | stock | `u:=q` | Δ |
|---|---|---:|---:|---:|---:|
| mc-5B | niah_single_1 | 0.288 | 0.933 (L14) | 0.911 (L0) | −2.22pp |
| mc-5B | niah_multikey_1 | 0.486 | 0.660 (L2) | 0.723 (L0) | +6.38pp |
| mc-5B | paired_S_multi | 0.286 | 0.813 (L14) | 0.625 (L7) | **−18.75pp** |
| mc-5B | **paired_D_multi** | 0.286 | **0.563 (L14)** | **0.500 (L4)** | −6.25pp |
| mc-30B | niah_single_1 | 0.288 | 1.000 (L15) | 0.867 (L15) | −13.33pp |
| mc-30B | niah_multikey_1 | 0.486 | 0.830 (L14) | 0.766 (L2) | −6.38pp |
| mc-30B | paired_S_multi | 0.286 | 0.688 (L14) | 0.500 (L4) | **−18.75pp** |
| mc-30B | **paired_D_multi** | 0.286 | **0.500 (L0)** | **0.500 (L9)** | 0.00pp |

- **핵심 셀인 paired-D에서 개선이 없다.** mc-5B는 0.563 → 0.500으로 1 flip 내려가고,
  mc-30B는 0.500 → 0.500으로 그대로다. 두 모델 모두 chance(0.286) 대비 여전히
  동전 던지기 근처다.
- **paired-S에서는 양 모델 모두 −18.75pp**(3 flips, n=16). 1-flip 노이즈 규약을 크게 벗어나는
  실질적 악화다.
- 유일한 개선은 mc-5B multikey의 +6.38pp(n=47 기준 3 샘플)로, 반대 모델에서 같은 크기의
  악화(−6.38pp)가 나므로 방향성 결론으로 쓸 수 없다.
- **판정: 스펙 §0.3의 처방 ①(`u_t`와 `q_t`를 묶기)은 기각.** "D 조건 읽기가 cos ≥0.98로
  온전하니 `q_t`는 key 정체성 정보를 갖고 있고, router가 그걸 그대로 쓰면 판별 신호를
  물려받는다"는 논증은 실측으로 성립하지 않았다. `q_t`가 key 정체성을 갖는다는 전제는 유지되지만,
  그 정보는 **mean-pool descriptor와의 내적으로는 꺼내지지 않는다.** 실패 지점은 query 쪽이
  아니라 descriptor 쪽이라는 뜻이며, 이는 아래 X1c·X2 결과와 일관된다.
- 조건별 provenance 주의: `stock`은 덤프의 canonical `stock_scores`를 그대로 쓴 값이고
  나머지 조건은 fp16 `u`/`q`/`c_full`에서 재계산한 값이다. 두 경로의 sanity 비교에서
  max abs diff 0.0515(tol 0.5, 3968 비교), top-2 집합 불일치 **64/3968 (~1.6%)** 이 나왔다.
  조건 간 ≤1 flip 차이는 노이즈로 취급해야 하는 이유다.

### X1c. anisotropy와 그 교정 — centering은 대수적 no-op, PC1 제거는 무효

- **anisotropy는 극단적이다.** descriptor Gram off-diagonal 평균 `mean_{i≠j}<ĉ_i,ĉ_j>`은
  8개 셀 × 16 layer **전부**에서 **0.958–0.9998** 범위다(최댓값 0.9998 @ mc-5B/single_1/L1).
  스펙 §2a의 트리거 임계 0.8을 모든 지점에서 넘는다. 모든 segment descriptor가 사실상 하나의
  방향을 공유하고, 판별 정보는 그 위의 미세한 잔차에만 실려 있다.
- **그런데 centering은 교정이 될 수 없다.** `c_i - mean_j(c_j)`를 선형 내적 점수에 적용하면
  한 샘플 안의 모든 eligible segment 점수가 **같은 상수만큼** 이동한다(`<query, mean>`이 i에
  무관하므로). 따라서 top-k와 hit@2는 **원리적으로 바뀔 수 없다.** 이것은 실험 결과가 아니라
  대수적 항등식이다. JSON에는 완결성을 위해 `stock_centered`/`u_eq_q_centered`를 남겨 두었으나
  그림에서는 뺐고, 값이 `stock`과 미세하게 다른 셀(예: mc-5B single_1 0.933 → 0.911)은
  centering 효과가 아니라 canonical-vs-recomputed provenance 차이(≤1 flip)다.
- **정보량이 있는 변형은 top-1 PC 제거다.** (sample, layer)마다 eligible 정규화 descriptor의
  top-1 우특이벡터 `v1`을 query와 모든 descriptor에서 사영 제거한 뒤 재채점한다. 이것은
  additive shift가 아니라 진짜 기저 변경이므로 rank-invariant가 아니다.

| model | dataset | stock | `u_recomp_pc1` | Δ | `u_eq_q_pc1` |
|---|---|---:|---:|---:|---:|
| mc-5B | niah_single_1 | 0.933 (L14) | 0.911 (L14) | −2.22pp | 0.933 (L13) |
| mc-5B | niah_multikey_1 | 0.660 (L2) | 0.660 (L2) | 0.00pp | 0.681 (L8) |
| mc-5B | paired_S_multi | 0.813 (L14) | **0.875 (L14)** | +6.25pp | 0.625 (L7) |
| mc-5B | **paired_D_multi** | **0.563 (L14)** | **0.563 (L14)** | **0.00pp** | 0.500 (L4) |
| mc-30B | niah_single_1 | 1.000 (L15) | 0.956 (L8) | −4.44pp | 0.911 (L15) |
| mc-30B | niah_multikey_1 | 0.830 (L14) | 0.830 (L14) | 0.00pp | 0.702 (L7) |
| mc-30B | paired_S_multi | 0.688 (L14) | 0.688 (L14) | 0.00pp | 0.563 (L4) |
| mc-30B | **paired_D_multi** | **0.500 (L0)** | **0.375 (L0)** | **−12.50pp** | 0.500 (L9) |

- **핵심 셀 paired-D에서 PC1 제거는 무효다.** mc-5B는 0.563 → 0.563으로 **완전히 동일한
  layer에서 완전히 동일한 값**(no-op), mc-30B는 0.500 → 0.375로 오히려 2 flip 하락한다
  (1-flip 규약 밖이지만 여전히 chance 인접이며 "회복"이 아니다).
- 유일한 개선은 mc-5B paired-S의 +6.25pp(1 flip) — 노이즈 규약 안이다.
- **판정: anisotropy는 확정, 값싼 기하 교정은 기각.** gram 0.96–1.0이라는 극단적 anisotropy가
  실재함에도, 지배 방향을 제거해도 숨어 있던 판별 신호가 드러나지 않는다. 이는
  "판별 신호가 지배 성분에 가려져 있다"가 아니라 **"판별 신호가 애초에 descriptor에 충분히
  들어 있지 않다"** 쪽을 지지한다. 스펙 §2a가 예측한 개선폭 `1/(1-⟨cos⟩)` 배는 관측되지 않았다.

## X2 — multi-query / multivalue key별 hit@2 (Tier 1): (M) 기각

원본: `results/x2_table.md`, `results/x2_verdict.json`, `results/x2_multiquery.json`,
`results/x2_structural.json`, 그림 `results/x2_layers_2048.png`. **이 실험이 0025의 결정적 결과다.**

### 무엇을 재는가, 그리고 두 개의 새 기준선

새 데이터 생성 없이 기존 RULER 태스크를 쓴다. multi-key와 multi-query는 needle 개수·배치가
같고 질문만 다르다 — multi-key는 여러 needle 중 하나만 묻고(정답 segment 1개), multi-query는
전부 묻는다(정답 segment N개). (M)이 참이면 `hit@2(multi-query) ≈ hit@2(single) ≫ hit@2(multi-key)`
가 나와야 한다. multivalue(key 1개, value 여러 개)는 **판별할 대상이 아예 없는** 극단 케이스다.

최종 정확도가 아니라 routing 레벨에서 잰다(스펙 §3). 해석을 위해 기준선 두 개를 추가했다.

- **needle-null (`needle_null_hit2`)**: 전체 과거 segment 위의 균등 분포가 아니라,
  **needle을 담고 있는 eligible segment들 위**의 균등 top-2. 공식은
  `mean_samples(min(1, 2/M))`, `M` = needle을 하나라도 담은 eligible segment 수. 곧
  **"needle 검출은 완벽, key 판별은 0"인 전략의 성능**이다. (M)이 서술하는 router가 바로 이
  전략이므로, (M)의 정직한 귀무가설은 chance가 아니라 이 값이다.
- **structural ceiling (`structural_ceiling`)**: routing 점수는 샘플당 **한 번** 계산되어
  하나의 top-2를 공유하는데 multi-query/multivalue는 정답 segment가 여럿이다. 따라서
  macro hit@2에는 1보다 낮은 구조적 상한이 존재한다(needle들이 같은 segment에 충돌하면
  `2/needle수`보다 클 수도 있다 — @2048에서 cur_seg가 4–7밖에 안 되는 소규모 birthday-paradox
  영역). `skill = (obs − chance)/(ceiling − chance)`로 정규화해 과제 간 비교를 맞춘다.

두 값은 모델과 무관하게 tokenization + annotation만으로 계산되며, 리뷰어가 독립 산출한
참조값과 **정확히 일치**한다(single_1/single_2 1.000, multikey 0.773, multiquery 0.750,
multivalue 0.723).

**(1) needle-null 미달이 1차 증거다.**

router가 못한다"**는 진술이다. **multivalue가 깨끗한 kill(~4 SE)** 이다 — 컨텍스트에 key가
정확히 하나뿐이라 판별할 것이 아무것도 없고, 모든 선택이 순수한 needle 검출인데도 router가

1차 증거는 (1) needle-null 미달과 (2) `single_2` 통제군이다.

## X3 / X5 — 보류 사유

스펙 §3 판정표의 **두 번째 행**이 적용된다.

> | multi-query hit@2 ≈ multi-key (둘 다 낮음) | **(M) 기각.** router가 needle 검출도 못 하는 것 →
> 문제는 key 판별이 아니라 descriptor 전반. X1c(centering)와 기하 교정이 최우선으로 승격되고
> **X3/X5는 보류** |

- **X3 (off-template anomaly probe)는 실행하지 않는다.** X3는 H_outlier와 H_template을
  가르는 실험인데, 두 가설은 **둘 다 (M)을 함의한다.** (M)이 기각된 이상 두 가설 모두 관측을
  설명하지 못하므로, 그 사이를 가르는 것은 무의미하다. 스펙 §4 자체가 "X2에서 (M)이 확정된
  경우에만 실행"으로 게이트되어 있다.
- **X5 (sub-block MaxSim P-sweep)도 실행하지 않는다.** X5는 X3가 H_template으로 판정된
  경우에만 메인으로 승격되는 조건부 실험이다. 전제가 성립하지 않는다. 덧붙여 X5의 논거는
  "판별 토큰이 256개 key 평균에 희석된다"인데, X2 multivalue는 **판별 자체가 필요 없는
  설정**에서도 실패를 보였으므로 granularity 세분화가 겨냥하는 병목이 지배적이 아니다.
- **다만 스펙이 예상한 승격 대상도 이미 소진됐다.** §3 판정표는 (M) 기각 시 "X1c(centering)와
  기하 교정"을 최우선으로 올리라고 했지만, X1c는 이번 라운드에서 **이미 실행되어 무효**로
  판정됐다(centering = 대수적 no-op, PC1 제거 = null-to-negative). 따라서 남은 것은
  재학습을 요구하는 처방들뿐이며, 다음 단계 설계는 사용자 결정 사항이다.
- H_outlier / H_template 자체는 **기각이 아니라 미검정 상태**로 남겨 둔다. 직접 증거(X3)가
  없기 때문이다. 다만 X1a의 간접 증거는 H_outlier에 **불리**하다 — layer 2–13에서
  `outlier_i` 단독 R² 중앙값이 0.097에 불과하고, PC1 제거도 효과가 없었다.

## X4 — random-routing MC ablation (실행 중)

> **⚠️ 실행 중 — 완료 시 갱신.** 아래는 목적·설계와 채워질 표의 뼈대뿐이다. 이 절의 수치는
> 아직 존재하지 않으며, `results/x4_random_routing.json`이 생성되면 `results/x4_table.md`를
> 통해 채운다. 영문 `report/0025.md`는 이 절이 확정된 뒤에 작성한다.

**목적.** 앵커 표에서 MC의 장문 single-needle 이득이 **routing 품질**에서 오는지, 아니면 segment당
write 부하가 256으로 상한되는 **구조적 효과**에서 오는지 분리한다. MC 5B의 S-NIAH-1은 8K→32K에서
회복되고 vanilla 5B는 붕괴하는데, 32K에서 vanilla는 state 하나가 32K를 흡수하고 MC는 각 state가
256만 쓴다. **routing이 완전 무작위여도 읽어낸 state가 더 깨끗할 수 있다.** 이 ablation 없이는
"MC의 이득이 routing에서 온다"는 문장을 쓸 수 없다 — 현재 앵커 세트의 최대 공백이다.

**설계** (스펙 §5, 가중치 재학습 없음 — 추론 경로의 top-k 선택만 교체):

- `stock`: 변경 없음 (sanity — 0024 E2와 동일 규약, `gold=None`일 때 byte-identical)
- `random`: 과거 segment에서 k=2개 균등 샘플, seed 5개 고정 (0,1,2,3,4)
- `recent`: 항상 가장 최근 k개 (위치 baseline)
- gate 규약은 0024 E2와 동일: `score = max(선택 최대, online)`
- 그리드: `niah_single_1`, `niah_multikey_1` × {1K, 2K, 4K, 8K, 16K, 32K} × {mc-5B, mc-30B},
  n_gen=128. (model × task) 4개 청크를 VESSL A100에서 순차 실행하며, 셀 단위 skip-existing
  재개(`x4_raw.json`)로 컨테이너 재시작에 견딘다.
- 동치성 게이트: incremental(stock) 생성 토큰열 == full re-forward greedy 토큰열
  (2048, 8샘플, VESSL에서 검증).
- 병기 기준선: `chance_upper = 2/(N−1) × 0.6`, `N = ctx/256`. `0.6`은 0024 oracle 범위
  0.31–0.56의 상한 근사(`conditional_EM`)다. **관측/상한 비율이 길이에 따라 커지면 routing이
  실제로 작동한다는 증거**이고, 평평하면 MC의 이득은 구조적 효과다.

**채워질 표 스켈레톤** (모델 × 태스크마다 1개, 총 4개):

|---|---:|---:|---:|---:|---:|---:|
| stock (EM%) | — | — | — | — | — | — |

vanilla-5B 앵커 행은 **다른 모델·다른 프로토콜**(collaborator 4-way 문서, memory caching 없는

"MC의 기존 이득이 routing 덕분"이라는 별개 주장은 철회해야 한다.

| **`u_t := q_t` 개선** | **기각** | X1b: paired-D 5B 0.563→0.500, 30B 0.500→0.500(개선 0); paired-S는 **양 모델 −18.75pp**; single 5B −2.2pp / 30B −13.3pp; 유일한 개선 mc-5B multikey +6.38pp는 30B에서 같은 크기로 반전 | 스펙 §0.3의 저비용 처방 ① 소멸. `q_t`가 key 정체성을 가져도 mean-pool descriptor와의 내적으로는 꺼내지지 않음 |
| **anisotropy** | **확정, 단 교정은 무효** | X1a: Gram off-diag가 8셀 × 16 layer **전부** 0.958–0.9998 (임계 0.8을 항상 초과). X1c: centering은 대수적 no-op(증명), PC1 제거는 paired-D에서 5B 0.563→0.563(동일 layer 완전 동일), 30B 0.500→**0.375** | 지배 방향을 제거해도 숨은 판별 신호가 드러나지 않음 → "가려져 있다"가 아니라 "애초에 없다". 값싼 후처리 기하 교정 노선 종료 |
| **MC 이득 = routing** | **진행 중 (X4)** | 미측정 — `results/x4_random_routing.json` 생성 대기 | 앵커 세트 최대 공백. 완료 전까지 "MC의 장문 이득이 routing에서 온다"는 문장 사용 금지 |

## 처방 업데이트

스펙 §0.2 분기표를 실측으로 채운 결과, **저비용 항목이 모두 소진됐다.**

**소멸한 후보**

1. **`u_t := q_t`로 묶기 — 기각.** X1b가 재학습 없이 검증했고, 핵심 셀 paired-D에서 개선 0,
   paired-S에서 양 모델 −18.75pp. 스펙 §0.3이 "논리 오류를 고친 반대 방향"으로 제시한 처방
   ①이었으나 실측이 지지하지 않는다.
2. **값싼 기하 교정(centering / top-1 PC 제거) — 기각.** centering은 top-k 순위에 대해
   대수적 항등으로 무효이고(실험이 아니라 증명), PC1 제거는 paired-D에서 no-op 또는 악화다.
   anisotropy가 gram 0.96–1.0으로 극단적임에도 그렇다.
3. **X5의 index granularity(sub-block MaxSim) — 우선순위 강등.** 전제(H_template)가 미확정인
   데다, 판별이 필요 없는 multivalue에서도 실패하므로 granularity가 겨냥하는 병목이 지배적이
   아니다. 스펙 §6의 kill-check(`P=32에서도 paired-D best-layer hit@2 < 0.6`)를 굳이 돌릴
   근거가 약하다.

**남은 후보 (둘 다 재학습 필요)**

1. **contrastive router supervision.** X2가 보여준 것은 descriptor에 판별 정보가 부족하다는
   것이고, LM loss만으로는 그 정보를 만들 유인이 없다(top-k가 미선택 segment의 gradient를
   차단하므로 신호 자체가 도달하지 않는다). "이 query에 대해 이 segment가 정답"이라는 신호를
   **직접** 주는 것 외에 descriptor에 판별 정보를 주입할 경로가 없다. 이제 이것이 **주 후보**다.
2. **WY/UT 읽기 기하 기준의 descriptor 재구성.** 0024에서 `qk_align ≈ 0`(−0.04~+0.06)인데,
   d=64 랜덤 방향의 코사인 표준편차가 `1/√64 = 0.125`이므로 **관측값은 잡음보다도 작다.**
   그런데 읽기는 작동한다(D 조건 read-cos ≥ 0.98). 설명 가설: GDN2는 delta rule 계열이라
   state를 `(I − β_t k_t k_tᵀ)` 곱으로 이전 key 성분을 지워가며 쓰므로, `v_{t*}`를 꺼내는 실제
   읽기 방향은 raw `k_{t*}`가 아니라 후속 key들에 의해 deflate된 방향이다. 즉 **descriptor를
   raw key 평균으로 두는 것은 backbone의 읽기 기하와 다른 공간에서 매칭하는 것**이다.
   처방은 "전용 projection 추가"가 아니라 WY/UT 표현 기준으로 descriptor를 구성하는 것이며,
   이 가설의 검정은 본 라운드 범위 밖이다. X1c의 결과(지배 방향 제거로는 신호가 안 나옴)는
   이 가설과 정합적이다 — 문제가 기저 회전이 아니라 **공간 자체**라면 사후 선형 교정으로는
   고쳐지지 않는다.

**순서 권고**: X4 결과를 먼저 확정한다. `stock ≈ random`이면 MC의 장문 이득 자체가 routing
덕분이 아니라는 뜻이므로 두 후보의 기대 수익 추정치가 바뀐다. 그다음 contrastive supervision을
1순위로, WY/UT descriptor를 그와 결합 가능한 2순위로 둔다.

## 한계

- **n이 작다.** paired-S/D는 조건당 16쌍, Dataset A와 X2 태스크는 40–50샘플(구조적 부적격
  샘플 제외 후). 절대값 주장은 하지 않았고 방향성으로만 서술했다. n=16 셀에서 1 sample flip은
  6.25pp이므로 그 이내 차이는 결론에 쓰지 않았다.
- **bf16 재실행 노이즈 ~2.3pp.** 예: E1과 X2가 독립적으로 재계산한 mc-30B `niah_multikey_1`
  per-layer hit@2는 16개 layer 중 14개가 bit-identical이고 layer 4·6이 정확히 ±1/47(=2.13pp)
  차이인데, 이 1샘플 flip 하나가 best-layer 인덱스를 14 → 4로 바꿨다. **best-layer 인덱스는
  노이즈에 불안정하다** — 값 자체는 훨씬 안정적이니 인덱스를 과해석하지 말 것.
- **best-layer는 16개 layer의 최댓값이라 상향 편의가 있다.** 모든 `se_hit2`/`se_skill`은
  실제 불확실성의 **하한**으로 읽어야 한다. macro_hit2가 0 또는 1인 경계 셀의 Wald `se`=0은
  공식 아티팩트이지 좁은 구간이 아니다.
- **`single_1`(noise-haystack) vs `single_2`(essay-haystack) 차이는 실재하는 부분 교란이다.**
  skill −0.167(5B)/−0.217(30B). 다만 needle 다중성 비용(−0.498/−0.497)의 약 1/2.5이므로
  전체를 설명하지는 못한다. 이 때문에 X2의 통제군은 `single_2`로만 쓰고 `single_1`은
  0024 연속성 참조로만 실었다.
- **X2 multiquery@2048은 hit@k가 60% 포화**(cur_seg = 4 = k)라, hit@k 원시값은 routing 신호를
  과대평가한다. 본문은 비포화 부분집합 값을 함께 실었다. multivalue는 28% 포화.
- **`niah_multiquery_q2`(q=2 스윕)는 깨끗한 k-only 조작이 아니다.** 질의된 needle 수만이 아니라
  **컨텍스트 내 needle 총수도 함께** 2개로 바뀐다. needle 수에 대한 단조 감소 주장은 철회했다.
- **X1의 조건 간 provenance가 섞여 있다.** `stock`만 canonical 덤프 점수이고 나머지 5개 조건은
  fp16에서 재계산한 값이다. top-2 집합 불일치가 64/3968(~1.6%) 관측됐다. `stock_pc1` 조건은
  존재하지 않는다(canonical 덤프에는 개입할 descriptor 공간이 없다).
- **X1c 트리거는 "off" 분기가 실데이터로 검증된 적이 없다.** gram ≥ 0.8 조건이 관측된 모든
  layer × dataset × model에서 발동했다(최솟값 ~0.958). off 분기는 단위 테스트로만 확인됐다.
- **Dataset B의 gold/distractor는 segment 1–5에만 배치된다**(0024 규약 유지). 양 끝단 미검증.
- **X4 미완**, X3/X5 미실행. H_outlier / H_template은 기각이 아니라 미검정 상태다.
- 학습 job은 한 건도 제출하지 않았다(스펙 §8 준수). "routing 공간 분리"는 스펙 §0.3에서
  철회된 처방이므로 제안하지 않는다.
