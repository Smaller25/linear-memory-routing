# 0020 — Salience-gated retention (constant-memory): oracle works, self-supervised signal doesn't, and from-scratch is a noisy testbed (2026-07-09)

After the multi-key analysis (long-gdn: chunk-mean-pool descriptor blurs the key a query wants; SSC
loses to vanilla on multikey at short L), the direction narrowed to **salience-gated retention**:
don't externalize/cache (that reintroduces O(N), cf. 0011/0019) — keep the needle in a **fixed**
recurrent state by not letting filler overwrite it. Constant memory, no cache. `GDN2LM.forward
(salience_gate)` scales each token's mixer input; low-salience (filler) tokens write weakly to the
state. Tested on irregular MQAR (`--ctx-filler 128`, sparse needle + long filler), GDN-2 d256/4L.

## Result (multi-seed, batch 64, 8000 steps)
| `--salience` | bootstrap | kv64 | kv128 | kv256 | kv512 |
|---|---|---|---|---|---|
| **none** (seeds 0,1,2) | **0 / 3** (loss 8.32 = random) | 0.00 | 0.00 | 0.00 | 0.00 |
| **surprisal** (seeds 0,1,2) | **0 / 3** (loss 8.32) | 0.00 | 0.00 | 0.00 | 0.00 |
| **oracle** (seed 0) | ✅ (loss → 0.000) | 0.966 | 0.591 | 0.129 | 0.031 |

For reference, 0015's *bootstrapped* vanilla on the same task: 0.82 / 0.30 / 0.06 / 0.01 — so oracle
salience beats a working vanilla at every kv (+0.11–0.19), but is still **capacity-bound** (degrades
with kv, the O(N) floor for >C facts stands).

## Findings
1. **The mechanism is sound (oracle).** Gating filler's write into the fixed state turns an (at this
   config) unlearnable diluted task into one that bootstraps reliably and recalls up to capacity — with
   **no cache, constant memory**. This is the constant-memory analogue of Track A single-needle SSC.
2. **The self-supervised (surprisal) signal fails — chicken-and-egg.** The gate signal comes from the
   model's own predictions, but the model can't bootstrap (0/3, loss stuck at random), so its surprisal
   is uninformative → gate ≈ uniform ≈ vanilla → never bootstraps. The 0018 drift wall in a starker
   form: the signal needs a trained model; training needs the signal.
3. **From-scratch MQAR bootstrap is a GPU-nondeterministic knife-edge.** Identical configs diverge
   (historical jobs 1249 loss 8.32 vs 1260 loss 0.000). Vanilla *can* bootstrap at easier settings
   (ctx-filler 64: loss 0.0007) but is unreliable at filler 128 with train-kv up to 64. This makes
   from-scratch a **noisy testbed** for the recall question: we cannot cleanly compare "salience vs
   vanilla recall" when vanilla's bootstrap is a coin-flip, and it denies surprisal a fair test (it
   never reaches a competent model whose surprisal would be meaningful).

## Verdict & next
- **Established:** oracle salience-gated retention is a working, constant-memory mechanism (beats
  bootstrapped vanilla, capacity-bound). The self-supervised surprisal gate does not survive
  from-scratch co-training (chicken-egg).
- **The clean test is on a FROZEN PRETRAINED model** (long-gdn GDN-1.3B): no bootstrap noise, and it
  (a) directly compares salience-gating (constant memory) against SSC-caching on Track A long-context
  retrieval, and (b) gives the surprisal signal a **fair test** — a competent frozen model's surprisal
  is informative, so "does surprisal-gating approximate oracle-gating at inference?" becomes answerable.
  Recommended next step.
