# 0027 — MC-SSC at 8K: two parameter-free routing fixes, 3.0 → 18.5 on diverse-key NIAH (2026-09-22)

0024 established, at length 2048, that MC-SSC(mean-pool) on GDN-2 370M fails multi-key NIAH because
of **routing**, using oracle injection as the causal test. This report extends that to **8192** (32
candidate segments instead of 7), supplies measured answers to H1/H2/H6/H7/H8 of
`notes/descriptor-hypotheses.md`, and reports **two fixes that work**. Both add zero parameters.

**TL;DR.** At 8K the sign of the multi-state advantage **inverts**: MC-SSC scores 2.3 where the same
backbone's single-state vanilla scores 18.7, while oracle injection scores 74.0 — the state holds the
answer and the router cannot find it. Sharing one layer's routing decision across all 16 layers, plus
scoring a segment by its best-matching 32-token sub-block instead of its 256-token mean, takes the
score **3.0 → 18.5** (paired, 200 items, 34 gained / 3 lost, p = 0.0000). That is 25% of the oracle
ceiling. The residual is read-side: selection reaches 0.640 while conversion stays at 0.328 against
the oracle's 0.67, and every intervention aimed at the read failed. Sub-block scoring is the
`multi-vector / late-interaction` cell that E3 recorded as untried; it has an **interior optimum at
m = 8**, so it is not the "finer chunks are better" move that `RESEARCH_STATE.md` dismisses as
synthetic-specific.

## 1. Relation to 0024–0026, and what is duplicated

This work ran in `gyunggyung/long-gdn` from 2026-08-19 and re-derived 0024's central finding without
consulting it. Stated plainly so the duplication is on the record:

| Already in 0024–0026 / `descriptor-hypotheses.md` | What 0027 adds |
|---|---|
| Routing is the dominant bottleneck; oracle injection is the causal test (0024) | The same at 8K, where the candidate count is 32 rather than 7 |
| H1 pooling destroys per-key identity | Quantified: a 6-token answer span is 2% of a 256-token mean; the fix is a granularity sweep with an interior optimum |
| H2 query-independence, fix candidate late-interaction MaxSim | **Measured.** m=8 sub-block max-sim, hit 0.325 → 0.450, p = 0.0059 |

| H8 cos is chance, signal is directional | `dot` beats `cos` as the scorer (part of a +0.06 hit gain) |

0024 is diagnosis. 0027 is diagnosis plus two fixes plus a catalogue of what does not work.

## 2. Setup

Same model and checkpoint as 0024: `LLM-OS-Models2/mc-gdn2-370m-fineweb-edu-30b-v2-meanpool`,
`checkpoint-30B-model-ckpt.pth`, config `mc_370M` (16 layers, `topk=2`, `mc_chunk_size=256`,
descriptor = mean-pool of L2-normalized keys), tokenizer `TinyLlama/TinyLlama_v1.1`. Model and kernel
code is now **vendored** at `dsc/` in this repository rather than imported from a long-gdn worktree.

**Task.** Diverse-key NIAH at length 8192 with 4 and 16 needles, every needle carrying a distinct key,
so "which key" is the whole difficulty. 32 segments, ~31 eligible candidates, chance hit@2 ≈ 0.065.

**Protocol.** Seeds 42/43/44, 50 items per cell, `n_gen` 48, `topk` 2, gate native, base and oracle
arms in the same run, router training restricted to a seed never evaluated.

This protocol is stated because it was not held earlier and that cost a month of comparability: the
same untouched baseline was measured as 4.0 (one seed), 2.3 (three seeds) and 3.0 (two clean seeds),
and the oracle as 82 and 74 under different runs. Numbers below are labelled with their arm count.

**Statistics.** All arms solve identical items, so comparisons are paired item-by-item with an exact
sign test, never independent-proportion standard errors. The paired detection floor is 6 discordant
items for p < 0.05, i.e. 12pp at n = 50 and 6pp at n = 100.

## 3. The failure at 8K

| arm | score | note |
|---|---|---|
| vanilla GDN-2, single state, N=4 | **18.7** | no cache at all |
| MC-SSC untouched | **2.3** | 3 seeds, 300 items |
| MC-SSC, gold forced into every layer's top-1 (oracle) | **74.0** | the state holds the answer |
| MC-SSC, dense read forced on the frozen model | **0.0** | membership is not retrieval |
| native routing hit@2 | **0.033** | chance ≈ 0.065 |
| cross-layer agreement on picks | **0.00** | 16 independent routers |

**The sign inverts with length.** 0024 measured MK-NIAH-1 at 2048: MC-30B 32 against vanilla 20 —
caching *wins*. At 8192 the same checkpoint loses to vanilla by 16 points. The candidate count rises
from ~7 to ~31 and routing decays with it, so the multi-state advantage is not a property of the
method but of how many segments the router must discriminate.

The dense row needs care: this is a model *trained* with top-2 and forced dense at inference, so it
measures dilution in a frozen read, not the quality of dense architectures. Log-Linear and DLA read
all states with learned weights and gain substantially on multi-key (DLA on Gated DeltaNet:
MK-NIAH-1 19.1 → 49.3 at 4K). Sparse reading is the efficiency claim, and sparse reading is what
breaks.

## 4. The two fixes

**Layer-shared routing.** The learnable gold signal is confined to the first layers: fitting a router
per layer on captured activations gives AUC 0.742 at L0 and 0.706 at L1, while L2–L15 land at
0.51–0.59, indistinguishable from the original linear connector refitted on the same tensors
(0.507–0.554). A 3M-parameter MLP and a single linear map score the same there, so this is missing
information, not missing capacity. Yet reading needs gold present in *every* layer: the oracle at
16/16 layers scores 82 while ~3/16 scores 4. Computing the decision once at L0 and having all 16
layers consume those indices — each keeping its own gate weights — moves N=4 from **4 to 18** with
the identical router (paired 8 gained / 1 lost, p = 0.039). It also cuts inference routing compute
16-fold.

**Sub-block descriptors (late interaction).** Store the mean of each 32-token sub-block instead of one
256-token mean, and score a segment by its best-matching block. Hit 0.325 → 0.450 on clean seeds
(paired, 51 gained / 26 lost, p = 0.0059, all four cells positive). Segment memory rises ~6%: the
state is 16 × 128 × 128 = 262k values against a 2048-value descriptor, so eight descriptors are
nearly free.

The granularity has an **interior optimum**, which is the answer to the "finer chunks are
synthetic-specific" objection:

| m | tokens per block | hit@2 | segment memory |
|---|---|---|---|
| 1 | 256 | 32.5 | +0.8% |
| 2 | 128 | 35.0 | +1.6% |
| 4 | 64 | 35.0 | +3% |
| **8** | **32** | **44.0** | **+6%** |
| 16 | 16 | 36.0 | +12% |
| 32 | 8 | 35.0 | +25% |

Not monotone. Finer is worse past 8, because a block mean over 8 tokens is a noisy estimate. m = 8 is
also the cheapest of the good settings. A second capture at 32 blocks, coarsened offline, reproduced
m = 8 at 44.0 against the deployed router's 45.0, so the gain is granularity and not the pipeline.

**Combined headline.** 3.0 → 18.5 (paired 200 items, 34 gained / 3 lost, p = 0.0000), against an
oracle of 74.0. N=16 moved for the first time, 4.0 → 12.0. The increment over the previous best
(13.5 → 18.5) is positive in all four cells but not yet significant on score (p = 0.1102, ~246 paired
items needed); it is significant on hit.

## 5. What does not work

Every attempt to put learned parameters on the **document** side loses. Four fits per variant,
paired by initialisation:

| variant | hit@2 | document params |
|---|---|---|
| fixed max-sim m=8 | **0.338** | 0 |
| per-head linear projection on the descriptor | 0.314 (loses 4/4, t = 3.07) | 262,144 |
| learned attention pooling over blocks | 0.223 | 2,049 |
| mean/max mixture, global scalar | 0.315 | 1 |
| mixture, per head | 0.306 | 16 |
| mixture, query-conditional σ(w·h) | 0.337 | D+1 (query side) |

The mixture is instructive. It contains both endpoints exactly — a = 0 reproduces the mean to 1.2e-7,
a = 1 reproduces max — yet the fitted a lands at 0.56 in both folds and beats neither. max wins
few_needles by +0.104 (4/4 runs, t = 3.8) and loses many_needles by −0.039 (1/4): the two regimes want
opposite aggregations and one global scalar cannot serve both. Making a query-conditional did not
adapt; it moved *further* toward max (0/4 on many_needles).

Also rejected: gate margin in both scopes (uniform destroyed the score, 13.5 → 3.5, p = 0.0000;
restricting it to the answer-producing segment still lost, 18.5 → 10.0); widening k alone (hit triples,
score falls 18 → 10); moving the shared source off L0; L0+L1 ensembles; a needle auxiliary loss;
an 8K-matched training set (hit 22.3% → 17.0%, p = 0.0070); training-free lexical key matching (GDN's
`k` is contextual, so chance).

**Methodological caveat that invalidated one of our own claims.** Offline probes that fit a head per
variant cannot resolve differences below ~0.02 on 196 items: two runs of a model verified identical to
1.2e-7 scored 0.311 and 0.327, because fp error accumulates over 8000 AdamW steps until the runs are
independent draws. A verdict drawn from a 0.021 gap was withdrawn. Probes now report mean and spread
over four initialisations.

## 6. The residual is read-side

Decomposing score = P(gold selected) × P(correct | selected):

| N | P(selected) | P(correct \| selected) | score |
|---|---|---|---|
| 4 | 0.450 → **0.640** | 0.295 → **0.328** | 20.0 → 25.0 |
| 16 | 0.200 → **0.260** | 0.095 → **0.231** | 7.0 → 12.0 |
| oracle | 1.0 | 0.67 / 0.69 | 67 / 69 |

Reading is threshold-like in gate weight, not graded: gold at 0.123 answers, at 0.046 it does not, and
the oracle gives it 0.536. Under shared top-2 the segment picked beside gold often takes more weight
(0.242 against gold's 0.123). This is why widening k trades hit for score, and why the margin lever —
which targets exactly this — still failed. **Perfect selection would leave roughly half the gap.**

## 7. Reproduced one scale down

`mc_50M` (52.1M non-embedding, 76.7M total; an isotropic shrink holding `ffn = 2d`,
`H·d_head = 2d`, `d_head = 128` and depth 16), FineWeb-Edu, 1.53B tokens at 20 tokens per parameter,
the anchor's recipe otherwise unchanged. Perplexity holds to four times the training length
(4K 27.2, 8K 26.5, 16K 30.8), so length extrapolation does not explain what follows.

Oracle 20.0 against untouched 0.33 (a factor of 60, against the 370M's 32), native hit 0.040 at
chance, cross-layer agreement 0.00. The failure shape transfers.

**One difference, stated because it limits transfer.** Learnable gold signal spans seven layers at 50M
(L0–L6 at 0.75–0.78, decaying to chance only by L15) against two layers at 370M. Part of the 370M
gain from layer sharing comes from two usable layers being outvoted by fourteen useless ones, and that
pressure is weaker at 50M, so a win there would overstate the anchor's gain.

## 8. Next — two method tracks, neither in H1–H8

**Track 1, surprisal-weighted descriptor (no training).** Weight the pooling by how surprised the
model was: `γ_i = Σ_j w_j·norm(k_j) / Σ_j w_j` with `w_j = (−log P(x_j|x_<j))^τ`. τ = 0 reduces
exactly to the current mean, so endpoint identity is checkable. Composes with m = 8: weight inside a
block, max across blocks. Zero parameters, which is the property every winning intervention here has
had.

Deployment cost is smaller than it looks. A completed segment's descriptor is read only by *later*
tokens, so the same forward pass's logits are causally available; routing cost is unchanged.

Risk: NIAH needles are "magic number for X is Y", so digits are structurally high-surprisal. A control
varying the needle format (numbers / UUID / words) is required before believing any gain.

**Track 2, learnable prefix/suffix soft prompt.** Prepend 4–8 trainable embeddings per segment to bias
what the state retains; backbone frozen, contrastive objective, only those embeddings trained.

The main risk is not decay but **distribution shift**: the backbone never saw soft prompts, and
injecting untrained embeddings across the prefill is the same class of intervention as the uniform gate
margin that destroyed the score while looking oracle-like at the query position. Mitigations, all
required: initialise near zero so `prefix → 0` reproduces the current model exactly; run a
prefix+suffix arm against prefix-only; and carry a **perplexity regression check**, which this project
has never needed before because no prior intervention touched the prefill.
