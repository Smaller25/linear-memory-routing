# 0012 — From-scratch Dynamic-MoSC: learned boundaries solve multi-key recall (2026-06-22)

Opens the **from-scratch track**. Reports 0005–0009 showed a hard-top-k read-out (SSC) over a
*frozen* backbone's cached state wins single-needle long-context — but 0010 found it does NOT extend
to multi-key recall ("MC caches one state per *segment*, not per *fact*; keys sharing a segment can't
be disambiguated"), and 0011 found it is not constant-memory. This report attacks the 0010 regime by
**co-training from scratch** with **content-adaptive segment boundaries** (Dynamic-MoSC), on a
**GDN-2** backbone. New code lives in `lmr/mosc/` (separate from the frozen `lmr/` track).

## Setup
- **Backbone:** FLA `GatedDeltaNet2` (GDN-2 generalises KDA and Gated DeltaNet v1: scalar gate → v1,
  vector gate → KDA). Pure-Triton → trains from scratch on RTX PRO 6000 Blackwell / sm_120, env
  `sh_routing` (torch 2.11+cu128, fla 0.5.2). 2 layers, d_model 128, head_dim 64.
- **Task:** Zoology-faithful MQAR (`lmr.tasks.mqar`), token-level multi-key recall. Train-kv 4–64,
  eval-kv 4–128, 6–8k steps. Recipe: lr 3e-3, wd 0.1, betas (0.9,0.95), grad-clip 1.0 (high lr is
  required — at 3e-4 every model pins at random loss).
- **Read-out:** hard top-k over a per-segment cache bank + `lm_head(base_h + read)`. Chunk modes:
  `fixed` (every C; = SSC control), `oracle` (a boundary at each context value = per-fact segments;
  the upper bound), `surprisal` (NLL peaks), `learned` (a `Linear(d,1)` head distilled from oracle
  positions). Segment summary is the pooled-hidden **proxy** (true-state check: §below).

## Phase 0 — does segment-level routing solve multi-key *at all*? (recall vs #kv)
| model | kv4 | kv8 | kv16 | kv32 | kv64 | kv128 |
|-------|----|----|-----|-----|-----|------|
| vanilla GDN-2      | 1.00 | 1.00 | 0.93 | 0.55 | 0.28 | —    |
| **oracle**         | 1.00 | 1.00 | **1.00** | **1.00** | **1.00** | **1.00** |
| fixed (C=64)       | 1.00 | 1.00 | 0.97 | 0.64 | 0.34 | 0.17 |
| surprisal          | 1.00 | 1.00 | 0.91 | 0.50 | 0.25 | 0.12 |

**PASS — but the whole win is boundary placement.** Oracle (per-fact segments) gives near-perfect
recall at every kv (0.997 @ kv128 vs vanilla 0.28 @ kv64) → segment-cache + hard-top-k **does** solve
the multi-key regime SSC failed in 0010. But `fixed` barely beats vanilla and `surprisal` (NLL peaks)
is no better than vanilla — neither finds fact boundaries. The open question reduces to a single
point: **learn boundaries that approximate the oracle.**

## Phase 1 — are the oracle boundaries learnable?
A `Linear(d,1)` head over the model's own hidden states, distilled from oracle positions
(pos-weighted BCE), using its own hard boundaries at eval.

- **First attempt FAILED** (train-kv 4/8 only): learned was *worse than vanilla* (kv16 0.50 vs 0.93).
- **Diagnosed = curriculum overfit, not threshold.** Boundary precision was ~1.0 but recall collapsed
  (0.52/0.31 @ kv16/32); the head fired only ~10 boundaries *regardless of kv* — trained on 4–8-fact
  contexts it learned a *position* bias ("fire on the first ~8 value-looking tokens"), not "is this a
  value". Lowering the eval threshold barely helped (it had nothing more to fire).
- **Fixed by widening the curriculum to train-kv 4–64 (8k steps):**

| model | kv4 | kv8 | kv16 | kv32 | kv64 | kv128 |
|-------|----|----|-----|-----|-----|------|
| oracle (ceiling)      | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |
| learned (kv 4/8)      | 1.00 | 1.00 | 0.61 | 0.31 | 0.15 | 0.08 |
| **learned (kv 4–64)** | 1.00 | 1.00 | **1.00** | **1.00** | **1.00** | **0.998** |

Boundary count now tracks kv (predicted 16.9/33.0/65.2/128.7 vs oracle 16/32/64/128; precision
0.84–0.99, recall 1.00, threshold-insensitive). **kv=128 was not in training → it generalises.**

**=> Boundaries are learnable.** A linear head over the backbone's hidden states recovers oracle-level
multi-key recall. The Dynamic-MoSC core mechanism works — closing the gap 0010 left open.

## Diagnosis trail (don't re-discover)
- All-models-fail-to-learn at first was **curriculum** (training straight on kv 16/32 fails to
  bootstrap), **not a kernel bug**: fla's gated-delta op test passes on sm_120 (10/10, fwd+bwd), and
  the read-out models trained to loss 0. Easy curriculum (train-kv 4/8) bootstraps; vanilla then shows
  a clean saturation curve.
- Legacy `lmr/scripts/train_mocm_mqar.py` (MoCMMixer) does NOT learn under fla 0.5.2 (silent, likely
  API drift) — off the from-scratch path; GDN2LM learns fine.

## Honest caveats / open
- **Segment summary is the pooled-hidden PROXY**, and the read-out is attention-lite over segments (a
  compressed-cache point on the RNN↔attention spectrum, cf. 0011) — so "mosc ≫ vanilla" is partly
  expected; the *scientific* signal is oracle/learned ≫ fixed/surprisal (same read-out, only boundaries
  differ). **Validity check IN PROGRESS:** swap the proxy for the TRUE GDN-2 recurrent state at each
  boundary (`backbone.run_segmented`, verified state-threading-equivalent to a full forward, 6.4e-4);
  jobs 1150 (oracle) / 1151 (fixed) running. Updates the verdict if oracle-true-state stays ~1.0.
- Boundaries are learned WITH oracle supervision (distillation). Unsupervised (task-loss-only / budget
  penalty) boundary learning is the next milestone.
- Single-needle long-context (passkey/RULER), parallel-pool routing (Mixture of Segment-Cache), and
  longer contexts are untouched here.

## Verdict
Multi-key recall — the regime frozen SSC could not reach (0010) — **is solved from scratch** by
GDN-2 + hard-top-k segment-cache read-out **when boundaries are placed per-fact**, and those
boundaries are **learnable** (learned ≈ oracle, generalising to unseen kv). Remaining: confirm with
true recurrent state (running), then remove oracle supervision. Code/run-state in `lmr/mosc/README.md`.
