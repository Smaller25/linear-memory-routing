# 0006 — Second backbone (Gated-DeltaNet) + new combine mechanisms (MoM / AoM / low-rank / hierarchical) (2026-06-17)

Through 0005 the whole Memory-Caching stack was welded to Mamba2: `segment_runner.py` reached
directly into mamba2 mixer internals (`in_proj`, `conv1d`, `A_log`, `_get_D`, RMSNorm gate). To test
whether cached-state routing is a property of *linear-recurrent models* rather than a mamba2 quirk —
and to explore richer ways of combining checkpoints — this phase (a) factors the architecture-coupled
code behind a per-arch **adapter** and adds a **Gated-DeltaNet** backbone, and (b) adds new
arch-agnostic read-out heads. No `fla/` files were edited.

## What changed
- **Adapter boundary at the *block*, not the scan.** `lmr/adapters/{base,mamba2,gdn}.py` define
  `project / scan / descriptor / finalize / run_block / vanilla_hidden`. The mamba2 math moved
  verbatim into `Mamba2Adapter` (no numeric change — existing GPU tests are the guard). The reason
  the boundary is the block: mamba2 blocks are mixer-only, but `GatedDeltaNetBlock` is
  `attn_norm → GDN → mlp_norm → MLP`, so the runner must drive the (recurrence-free) MLP sublayer
  too. `run_segmented_lm(..., arch=)` dispatches the adapter; the read-out heads are unchanged.
- **GDN memory isolation by zeroing `v`.** The mamba2 cache loop isolates a checkpoint's
  contribution by zeroing the value path and injecting the checkpoint as the initial state (exact by
  SSD linearity). The gated-delta state is likewise affine in its initial state for fixed inputs
  (`h_i = decay_i(I − β_i k_i k_iᵀ) h_{i−1} + β_i k_i⊗v_i`), so zeroing `v` yields exactly the
  cached state's contribution. Proven on CPU against the reference op in `test_gdn_superposition.py`.
- **New read-out heads** (`lmr/readout.py`, arch-agnostic): **MoMReadout** (route each checkpoint to
  one of M bounded slots, per-token softmax gate over slots + optional shared slot, Switch aux),
  **AttentionOverMemories** (softmax attention of a query over checkpoint descriptors). Every trained
  head (GRM/SSC/MoM/AoM) gained a **`low_rank_dim`** option factoring `hidden→r→descriptor_dim`
  (~25× fewer params at 1.3b: full router ≈805M, r=64 ≈31M) — default-on in the scripts. Full-rank
  keeps the legacy `W_u.weight` key, so 0005's SSC checkpoint still loads.
- **HierarchicalCache** (runner-side flag `--hierarchical-k`): summarize every K completed segments
  into one coarse checkpoint (their sum = RM-merge by linearity), bounding checkpoint growth and
  adding a long-range scale. Pure helper `checkpoint_list` (CPU-tested).
- **Loader + scripts**: `lmr/loaders.py` (`load_backbone(arch)`; GDN via FLA-native
  `from_pretrained`, tokenizer from the checkpoint — *not* gpt-neox). `eval_long.py` /
  `train_grm_passkey.py` gained `--arch {mamba2,gdn}`, `--variant {grm,ssc,mom,aom}`,
  `--low-rank-dim`, `--hierarchical-k`.

## Correctness gates
- **CPU** (`pytest tests/lmr`, no GPU/Triton): GDN `v=0` superposition; `gdn_meanpool_state`;
  `checkpoint_list` flat/hierarchical; MoM/AoM shape+aux; low-rank vs full shape & param count;
  full-rank legacy key. Existing mamba2 readout/scan/converter tests unchanged.
- **GPU** (`test_segment_runner_gdn.py`, mirrors the mamba2 file): (1) GDN `run_block` (empty cache)
  ≡ `GatedDeltaNetBlock` forward; (2) RM ≡ vanilla at N=1; (3) multi-segment memory changes logits.

## A100 validation (2026-06-17)
Ran the suite + GDN load + baselines on the A100.
- **Tests: 29 passed, 1 failed** (the failure is the pre-existing `test_mom_adapter` FLA-MoM-arm
  edge case — short seq in train mode — unrelated to this phase). **The new GPU gates pass**:
  GDN `run_block ≡ GatedDeltaNetBlock.forward`, GDN RM ≡ vanilla at N=1, multi-segment changes
  logits; mamba2 regression tests still green (the verbatim refactor is clean).
- **GDN load fixes (needed; not caught off-GPU):** (1) `_tied_weights_keys` list→dict in
  `fla/models/gated_deltanet/modeling_gated_deltanet.py` (transformers 5.12, same as mamba2); (2) the
  `linear-moe-hub/Gated-Deltanet-1.3B` checkpoint is old-FLA — `load_gdn` now splits the fused
  `mlp.gate_proj` (2·inter) → `gate_proj`+`up_proj` and drops the obsolete per-head `attn.D` skip;
  (3) it ships no tokenizer → use the **Mistral** tokenizer it was trained with (vocab 32000). Loaded
  model is coherent and recalls a short passkey ("…The pass key is 48217") — conversion functionally OK.
- **Key finding — GDN-1.3b is far more long-context-robust than mamba2-1.3b.** Vanilla passkey:

  | length | 1024 | 2048 | 4096 | 8192 | 16384 | 32768 |
  |--------|------|------|------|------|-------|-------|
  | mamba2-1.3b | 1.000 | 1.000 | 1.000 | 0.738 | — | — |
  | **GDN-1.3b** | 1.000 | 0.984 | 1.000 | 0.93–0.96 | **0.771** | **0.594** |

  GDN (delta-rule + gating) holds ~0.93 at 8k where mamba2 has dropped to 0.738; it only degrades
  meaningfully at **16k–32k**. Training-free RM degrades GDN too (8192: 0.604) but less catastrophically.
- **Implication:** the MC net-win test for GDN must target **16k/32k** (where vanilla collapses), not
  8k.
- **⚠️ Blocker — GDN router TRAINING is OOM on the A100.** `chunk_gated_delta_rule` *backward* needs
  **225,540 B** shared memory > A100's **166,912 B** limit (GDN-1.3b has `head_dim=256` vs mamba2's
  64; this checkpoint was trained on H100-class shared memory). GDN **forward/inference is fine**
  (vanilla + training-free RM eval all run), so only the *trained* heads (GRM/SSC/MoM/AoM) on GDN are
  blocked. Options for next time: (a) run GDN training on an H100; (b) reduce the chunk-kernel block
  size (smaller `BT`) so the backward fits A100; (c) `fused_recurrent` backend for the backward; or
  (d) keep GDN as a *forward-only / RM* arm and do trained-router comparisons on mamba2 (130m/1.3b/2.7b).
- **GDN status: framework validated, backbone competent + long-context-robust; trained-router GDN
  deferred on this hardware.**
