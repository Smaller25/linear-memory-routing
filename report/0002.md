## Phase 0b — in-distribution natural-language passkey (the clean test)
The synthetic tasks above use random token ids (OOD for a text LM). `lmr/tasks/make_text_passkey`
+ `scripts/eval_text_passkey.py` build a real English NIAH prompt (gpt-neox tokenizer) so the
pretrained model is in-distribution. Right-padded (mamba RIGHT-pad rule). 64 ex/length, chunk 256:

| length | vanilla | +MC-RM | Δ | segments@256 |
|--------|--------|--------|---|--------------|
| 512  | 0.993 | 0.986 | −0.007 | 2 |
| 1024 | 1.000 | 0.986 | −0.014 | 4 |
| 2048 | 1.000 | 0.780 | −0.220 | 8 |
| 4096 | 1.000 | **0.199** | **−0.801** | 16 |

**Vanilla solves the natural-language passkey ~100% to 4k** (the eval is now meaningful — opposite
of the noise-floor synthetic numbers). **MC-RM degradation scales monotonically with segment count**
(2 seg ≈ free, 16 seg → catastrophic −0.80). (8192 OOM'd: the runner materialises full-vocab fp32
logits over all segments — an eval-memory issue to fix by scoring only labelled positions, not a
mechanism problem.)

## Conclusion (honest)
**Training-free MC-RM does NOT improve recall on a pretrained mamba2 — and on the clean
in-distribution test it actively HURTS, monotonically with segment count** (1.000 → 0.199 at
4k / 16 segments). This is expected, not an implementation bug:
- The frozen model was never trained with a **segment-reset + summed-cache read-out**; each extra
  cached contribution inflates the SSM output before RMSNorm, so error grows with #segments. RM is
  "free" only for memories *trained* that way (the MC paper's setting).
- The synthetic random-token tasks were additionally OOD (vanilla at noise floor); the
  natural-language passkey fixes that (vanilla ~100% to 4k) and isolates the effect cleanly.

→ Strong motivation for **Phase 1** (train the GRM gate / SSC router so cached memory is *used*
without destroying the base read-out; backbone frozen). The mechanism, loader, and both evals
(synthetic + in-distribution) are verified and ready. TODO: score only labelled positions in the
runner to avoid the full-vocab logit OOM at ≥8k.
